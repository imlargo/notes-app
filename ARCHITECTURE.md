# Architecture

The layers exist so the logic and the persistence never touch React. domain/ is the model and the geometry, pure functions I can check without mounting anything. I put the clamping and the drag maths there. services/ hides persistence behind an async NoteRepository, and both implementations fake latency so the UI is written against real async I/O, which is also why a REST backend would be one more class and nothing above it changes. The hooks are split by what each one needs to know rather than by size. useNotes owns the data, useBoardGestures owns the pointers and knows nothing about persistence, and useBoardBounds sits outside both, because gestures and keyboard commands clamp against the same board.

Every write is optimistic. The screen updates first, the repository after, and a failure puts the previous value back. Text is the exception, reverting what someone typed because a save failed is worse than a stale disk. Writes carry only the changed fields and the response is thrown away, so typing while a move is still in flight cannot be overwritten by its own echo. A note also exists before the repository has answered, so it carries a negative id until the real one arrives, and no write for that id ever leaves the browser. On the interaction side there is one set of pointer handlers on the board and none on the notes, and the gesture is a union kept in a ref, since it changes on every pointermove and nothing renders from it. What gets committed comes from the gesture instead of from reading state back, so a commit never waits on React having rendered the last move. Notes are read through a ref for the same reason. notes is a new array every frame, and closing over it would give every callback a new identity and re-render all of them.

Accessibility shaped the component API rather than following it. Every note is focusable and can be moved, resized, edited and deleted without a mouse, one tab stop each, since thirty notes with two stops is sixty stops to cross a board. The selection has its own outline, because the colour control means two different things depending on whether a note is selected and focus-visible cannot show which. Successes go to a polite live region, failures to role=alert, never both. The tests run without React, so domain/ and the reducer are checked directly, and the two repositories share one contract suite that runs twice. That is what keeps catching them disagreeing. One reused the id of a deleted note, both reported success for an update to a note that was not there so the rollback could never fire, and one let a draft bring in its own id. What that leaves uncovered is the gesture wiring, which cannot be reached without a DOM, and that is the next thing to write.
