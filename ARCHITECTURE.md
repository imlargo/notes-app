# Architecture

The app is layered so the logic and the persistence don't depend on React. domain/ is the model and the geometry, pure functions I can test without mounting anything. services/ hides persistence behind an async NoteRepository with two implementations, in-memory and localStorage, both with fake latency on purpose so the UI is written against real async I/O. A REST backend would be one more class and nothing above it changes. hooks/ is split by what each part needs to know rather than by size: useNotes owns the data, useBoardGestures owns the pointers and knows nothing about persistence, useBoardBounds sits outside both because gestures and keyboard commands both clamp against the board, and useBoard composes them.

Persistence follows one policy instead of two. Moving a note used to be optimistic while creating and deleting waited for the round trip, and that inconsistency was worse than either choice on its own, since the app taught you two different things about whether your action had landed. Now every write updates the screen first and the repository after, creating hands the note a temporary negative id so it appears immediately and swaps it in place for the stored one so the z order survives, and a failure puts the previous value back and says why. Text is the one exception and it is deliberate: reverting what someone typed because a save failed is worse than a stale disk, so a failed text write only reports. Rolling back machine generated state is cheap, rolling back a person's input is not.

Writes carry only the changed fields and the response is thrown away. Sending the whole note and applying the echo loses data in a way that is easy to miss, drop a note and start typing while the 500ms write is in flight and the response puts the old empty text back on screen. The diff protects the disk since the repository merges instead of overwriting, and ignoring the response protects the screen since the client already has the value it just wrote and anything arriving later can only be older.

The main decision on the interaction side was to drag with one set of pointer handlers on the board instead of wiring listeners per note. Hit testing happens on pointerdown and the current gesture is a union kept in a ref since it changes every frame and nothing renders from it, and the repository is only written when the gesture ends. The gesture hook receives preview and commit as callbacks, which puts the hot path rule in the signature: preview runs every frame and stays local, commit runs once and is the only thing that reaches the repository. The final geometry comes from the gesture rather than from reading state back, otherwise the commit depends on React having rendered the last pointermove, which it usually has, which is exactly the kind of thing that breaks once under load and never reproduces. Notes are read through a ref for the same family of reasons: notes is a new array every pointermove, so any callback closing over it gets a fresh identity per frame and the memo on StickyNote compares eight props, finds them all different, and re-renders all thirty notes sixty times a second.

Accessibility wasn't an afterthought, it shaped the component API. A drag only interface is invisible to a keyboard so every note is focusable and can be moved, resized, edited and deleted without a mouse, and focus lands somewhere sensible after a note disappears. One tab stop per note on purpose, the textarea is tabIndex -1 until you press enter, because thirty notes with two stops each is sixty stops to cross a board. Selection is drawn rather than implied, since the colour control means two different things depending on whether a note is selected and focus-visible cannot show which, it disappears the moment you click with a mouse. Blur deliberately does not clear the selection either, tabbing to the toolbar would kill it on the way and the picker would be unreachable by keyboard. The picker itself is native radios in a fieldset so the arrow key navigation and the grouping come from the browser, successes go to a polite live region and failures to role=alert but never to both, or a screen reader announces them twice. Types work the same way, the gesture is a union instead of a pile of flags so the wrong state doesn't compile.

What is missing is the test suite. Geometry, the reducer, the gesture maths and the repositories were all written to be checkable without React, which is the hard part, but wiring it up is still pending and it is the first thing I would do next. Notes also come back inside the board the next time you move them rather than when the window shrinks under them.
